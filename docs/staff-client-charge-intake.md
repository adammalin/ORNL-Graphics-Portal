# Staff client submission and charge capture

Verified Graphics staff (designer, coordinator or admin), with current native edit access and pilot write checks, can select **Submit on behalf of a client**. Client name/email and organization are written to the existing native Requestor, Requestor Email and organization fields. Without that explicit boolean selection, create continues to overwrite requester identity with the verified staff identity.

The immutable submitter remains the server-verified actor in the original confirmed create receipt in `portal_assignment_events`. The staff detail view exposes that original actor independently of the current client. No email/name edit transfers creator ownership, assignment acceptance or Microsoft My Requests access. Historical jobs without a verified creation receipt show **Not recorded**, rather than guessing a submitter. Renaming a client does not grant that client a login or tracking receipt.

Staff can enter or edit a charge number. It uses the existing native **Charge #** text column. No sheet schema, formulas, automation definitions or permission settings are changed. Codes are trimmed and limited to 80 letters/numbers, spaces, dots, slashes, underscores and hyphens. Capture is not billing validation; the UI displays **Pending validation**, with no verified status control or SCOUT lookup. Blank is allowed while a code is unresolved.

The existing staff edit dialog permits correcting a selected existing DEV request's client and charge. It uses normal revision/idempotency guards and retains attachments, source details, dates and assignment unless explicitly edited. The employee Microsoft intake endpoint rejects staff-only onBehalfOf, submittedBy and chargeNumber payloads and continues to bind identity to the authenticated employee.

Validation covers native cell mapping, fresh-session readback, original submitter preservation after edit, creator permissions, unrelated-row preservation, invalid client/code rejection, readonly/paused writes, duplicate/replay handling and employee forgery rejection. Use an explicitly authorized synthetic DEV request for further live qualification. Client-specific comparison receipts, original requested dates and external job identifiers stay in the private test library; do not copy them into public fixtures. A browser readback is not independent native cell/formula verification.
